Credentials By-Reference in the Messaging Layer Security (MLS) Protocol
                draft-mahy-mls-credential-by-ref-latest

Abstract

   Credentials in MLS can grow to become quite large.  Many credentials
   appear repeatedly in several MLS groups.  This extension allows MLS
   credentials to be included by using a hash reference of the actual
   credential.

1.  Introduction

   This new credential type allows an MLS LeafNode to contain a hash
   reference to another MLS credential.  This could be be communicated
   out-of-band or in another MLS group.

2.  Conventions and Definitions

   The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
   "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and
   "OPTIONAL" in this document are to be interpreted as described in
   BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all
   capitals, as shown here.

3.  Credential Format

   struct {
       CredentialType referenced_credential_type;
       HashReference referenced_credential_hash<V>;
   } ByRefCredential;

   by_ref = ByRefCredential;

   The referenced_credential_hash is the hash of the entire Credential
   struct of the referenced_credential_type, using the hash function
   from the cipher suite of the KeyPackage or the MLS group.

   The referenced_credential_type MUST NOT be a by_ref Credential type.

4.  Security Considerations

   The security of this mechanism depends on the strength of the hash
   function's resistance to birthday attacks.

   Clients implementing this extension need to consider that the lookup
   of credential hashes could potentially leak timing information.
   Implementations must be careful that the scope of applicability (ex:
   the audience in a web token, or the domain in an X.509 certificate)
   is relevant to the context of the LeafNode (in an MLS group or in a
   KeyPackage).
